# Журнал гипотез

`hypotheses.jsonl` — append-only журнал проверенных идей: одна строка JSON на попытку.
Правка и удаление строк запрещены, файл коммитится вместе с отчётом прогона.

Зачем: поправка на множественную проверку должна считать попытки по файлу, а не по
флагу `--trials`. Самоотчёт легко занизить, а новое имя стратегии обнуляло бы счётчик.
Дизайн — `docs/EVALUATE_DESIGN.md`, решение — ADR-029.

Правила счёта:

- бюджет — **20 идей** на календарный квартал (`TRIAL_BUDGET_PER_QUARTER`); тратят его
  только записи `kind="idea"`, одна запись = одна идея. Широкая сетка TP/SL внутри идеи
  бюджет не увеличивает;
- `grid_cells` — сколько ячеек сетки просмотрено внутри идеи. Информационное поле отчёта
  и вход поправки на screening-ступени, **не** единица бюджета: heatmap из 20 ячеек —
  одна идея, а не 20;
- счётчик идей глобальный: по всем стратегиям и вселенным, не по паре «стратегия + идея»;
- `kind="sealed"` — обращение к запечатанному OOS (после `2026-10-01`). Бюджет не тратит
  (это не новая идея, а подтверждение), но увеличивает `k` для поправки `0.05 / k`;
- `record_attempt()` бросает `TrialBudgetExceeded` **до** записи: прогон, который
  превысил бы бюджет, не начинается.

Защита от переписывания:

- каждая строка содержит `prev_hash` — SHA-256 канонического JSON предыдущей строки,
  первая — `GENESIS_HASH` (`0`×64);
- `load_hypotheses()` проверяет цепочку при каждом чтении; правка, удаление или
  перестановка строк даёт `broken hash chain` с номером строки;
- пересчитать цепочку после правки можно только переписав все последующие строки —
  это видно в `git diff`, а не прячется;
- **предел защиты:** цепочка не спасает от пересоздания журнала целиком — тот, кто
  пересчитает все `prev_hash` с нуля, получит валидный файл. Для личного проекта этого
  достаточно; следующий уровень — фиксировать последний хеш вне журнала (в сообщении
  коммита или отдельным файлом) и сверять.

После каждого запуска `evaluate`:

- **пользователь** коммитит `journal/hypotheses.jsonl` **сразу** после прогона, в той же
  ветке и в том же коммите, что и отчёт. Откат ветки, `git checkout` или `git stash`
  без коммита обнуляют счётчик и обесценивают поправку;
- `evaluate` сам **не коммитит** (команда, пишущая в git, может захватить лишнее),
  а только определяет незакоммиченные строки (`git status --porcelain journal/`) и печатает
  предупреждение с их числом. Если git недоступен (запуск вне репозитория), печатается
  «git недоступен, проверь журнал вручную» — молчать нельзя;
- когда появится `docs/OPERATIONS.md` (T6-7), правило переезжает туда, здесь остаётся
  ссылка.

Запись делает `src/backtest/hypothesis_log.py::record_attempt()`; вручную строки
не добавляются. Первая запись должна перечислить гипотезы, проверенные до введения
журнала (они известны по `docs/TASKS.md` и отчётам `debug/`).
